How to request work from the process that owns a box¶

Some state belongs to one process. The process that drives a camera knows its temperature, and it decides which exposure the camera uses, so other processes should read that state and ask for changes, not write it themselves. An attribute gives you both: its owner publishes a value that every process reads, and other processes send it requests that the owner acts on and answers. This guide declares attributes, publishes them, serves their requests and handles what can go wrong.

1. Declare an attribute¶

Annotate the field Attr[T], with T the type of its value, or Setting[T] when other processes may ask to change the value, and declare it with attr(). An attribute that takes arguments lists their types after T, and one that only carries out a command has a T of None:

import asyncio
import threading

from sharedbox import (
    Attr,
    RequestError,
    RequestSupersededError,
    Setting,
    SharedBox,
    attr,
)


class Camera(SharedBox, name="example-camera"):
    temperature: Attr[float] = attr()
    exposure: Setting[float] = attr(default=0.01)
    move: Attr[float, [float]] = attr()
    home: Attr[None] = attr()

Every attribute with a value stores the time of each publish of the value. A Setting also holds a setpoint of the same type as the value, which other processes ask to change with set. An attribute starts at the zero of T, or at default, which also gives a Setting its starting setpoint. A T with no zero, such as a record without defaults, needs a default.

The box's constructor has no parameter for an attribute, because only its owner writes it. Reading camera.exposure gives the object through which this box's exposure is published, read and asked for work: a Setting here, an Attr for temperature, and the same object every time. A Setting is a kind of Attr, so everything below about an Attr holds for it too. Assigning to the field or passing it to update raises TypeError. T and the argument types may be any type a record member may be, except another Attr or a reference to a box. T may not be a Timed either, since the attribute already stores the time of each publish.

An attribute takes requests when it has argument types, when its T is None, or when it is a Setting. In the Camera above, move and home take requests through a call, exposure through set, and temperature takes none. A Setting's request carries the new value as its one argument, so a Setting takes no argument types and its T cannot be None.

2. Publish its value¶

The owner writes an attribute with publish, which takes the parts by keyword and writes all of them in one write, so a reader never sees a value next to a setpoint from a different publish. Any process reads the parts with value, timestamp_ns and, on a Setting, setpoint, or all of them from one write with read:

camera = Camera()
camera.temperature.publish(value=21.5)
print(camera.temperature.value)  # 21.5
reading = camera.temperature.read()
print(reading["value"], reading["timestamp_ns"] > 0)  # 21.5 True

A value published without timestamp_ns is stamped with the time of the write. Give timestamp_ns when the device reports its own time. A publish of the setpoint alone keeps the value and its time.

watch and events report publishes with the AttrValue that read returns, as they report writes of any field: several publishes in quick succession may reach you as one change, with the parts of the last. snapshot includes the AttrValue too. A request is not an event, so it reaches neither. Nothing checks which process publishes, so keep publish in the owner's code.

3. Serve it¶

The process that owns the device registers a handler with serve. A Setting's handler receives the value given to set:

def set_exposure(value: float) -> float:
    accepted = min(max(value, 0.001), 1.0)
    camera.exposure.publish(setpoint=accepted)
    camera.exposure.publish(value=accepted)
    return accepted


def move(target: float) -> float:
    if target > 100.0:
        raise ValueError(f"{target} is out of range")
    return target


exposure_server = camera.exposure.serve(set_exposure)
move_server = camera.move.serve(move)

Answering a request publishes nothing, so the handler publishes what other processes should see. set_exposure publishes the setpoint it accepted and then the value, and a handler for a real camera would configure it between the two, so readers see the request accepted before the camera uses it.

A plain function runs on a thread of its own, so a slow handler doesn't hold up what watch and events deliver. An async def handler runs as a task on the event loop that is running when you call serve, and calling serve with one outside a running loop raises RuntimeError. Only one process serves a field at a time: a second serve while a live process serves it, this one included, raises AlreadyServedError.

RequestServer.stop stops serving and frees the field for another server. It waits for a running plain handler to finish and answer first, and it asks a running async def handler to cancel, whose caller then gets RequestError. Closing the box stops every server it started, and so does garbage collection of the box or the end of the process, but these free the field at once: a request whose handler is still running fails with RequestError saying the server stopped, and only then does the close wait for a plain handler's thread.

4. Send a request¶

Calling the attribute, or set on a Setting, sends the request at once and returns a RequestFuture, which you wait on with result in any thread or await in a running event loop:

print(camera.exposure.set(5.0).result(timeout=5))  # 1.0
print(camera.exposure.setpoint)  # 1.0
print(camera.move(5.0).result(timeout=5))  # 5.0


async def main() -> None:
    print(await camera.exposure.set(0.02))  # 0.02


asyncio.run(main())

The request is sent whether or not anyone waits for the future, and cancelling the future only stops the wait. A request takes positional arguments only, so give a time limit to result(timeout=...), or to asyncio.wait_for in async code. A request sent while nobody serves the field waits until a server starts.

5. Handle a failed request¶

An exception the handler raises is logged to the sharedbox logger in the serving process, with its traceback, and reaches the caller as RequestError, with the exception's type and message cut to 256 bytes:

try:
    camera.move(250.0).result(timeout=5)
except RequestError as error:
    print(error)  # Camera.move: ValueError: 250.0 is out of range

A caller waiting on a server whose process ends gets ServerExitedError within about a tenth of a second. A server that stops while it handles a request answers that request, as section 3 describes, so no caller waits for an answer that can't come.

6. Expect the latest request to win¶

The handler handles one request at a time. Of the requests sent while it runs, only the newest is handled next, and each one before it raises RequestSupersededError in its caller. The same holds while no server runs: the field keeps one request, so a request that a later one replaces raises that error at once, and only the newest waits for the server to start. A camera told to move to 2 and then to 3 while it is still moving goes to 3:

started = threading.Event()
release = threading.Event()


def slow_move(target: float) -> float:
    started.set()
    release.wait()
    return target


move_server = camera.move.serve(slow_move)
first = camera.move(1.0)
started.wait()
second = camera.move(2.0)
third = camera.move(3.0)
release.set()
print(first.result(timeout=5), third.result(timeout=5))  # 1.0 3.0
try:
    second.result(timeout=5)
except RequestSupersededError:
    print("the second request was superseded")

If every request has to run, wait for each answer before sending the next.

The whole script 
"""The script of the guide "How to request work from the process that owns a box"."""

import asyncio
import threading

from sharedbox import (
    Attr,
    RequestError,
    RequestSupersededError,
    Setting,
    SharedBox,
    attr,
)


class Camera(SharedBox, name="example-camera"):
    temperature: Attr[float] = attr()
    exposure: Setting[float] = attr(default=0.01)
    move: Attr[float, [float]] = attr()
    home: Attr[None] = attr()



camera = Camera()
camera.temperature.publish(value=21.5)
print(camera.temperature.value)  # 21.5
reading = camera.temperature.read()
print(reading["value"], reading["timestamp_ns"] > 0)  # 21.5 True


def set_exposure(value: float) -> float:
    accepted = min(max(value, 0.001), 1.0)
    camera.exposure.publish(setpoint=accepted)
    camera.exposure.publish(value=accepted)
    return accepted


def move(target: float) -> float:
    if target > 100.0:
        raise ValueError(f"{target} is out of range")
    return target


exposure_server = camera.exposure.serve(set_exposure)
move_server = camera.move.serve(move)

print(camera.exposure.set(5.0).result(timeout=5))  # 1.0
print(camera.exposure.setpoint)  # 1.0
print(camera.move(5.0).result(timeout=5))  # 5.0


async def main() -> None:
    print(await camera.exposure.set(0.02))  # 0.02


asyncio.run(main())

try:
    camera.move(250.0).result(timeout=5)
except RequestError as error:
    print(error)  # Camera.move: ValueError: 250.0 is out of range

move_server.stop()

started = threading.Event()
release = threading.Event()


def slow_move(target: float) -> float:
    started.set()
    release.wait()
    return target


move_server = camera.move.serve(slow_move)
first = camera.move(1.0)
started.wait()
second = camera.move(2.0)
third = camera.move(3.0)
release.set()
print(first.result(timeout=5), third.result(timeout=5))  # 1.0 3.0
try:
    second.result(timeout=5)
except RequestSupersededError:
    print("the second request was superseded")

move_server.stop()
exposure_server.stop()
camera.close()
Camera.unlink()
