Streams¶

Name What it does
SharedStream a named ring of typed items in shared memory, sent by one process and received by up to max_readers readers
StreamSender the one sender of a stream, with blocking, non-blocking and asyncio sends
StreamReader a reader of a stream, in mode lossless, lossy or latest
ReaderEvents the psygnal signal group of a reader: received for each item and ended once
StreamStatistics a stream's state at one moment: what was sent, what the ring holds and who reads it
ReaderStatistics one open reader of a stream: its mode, position, lag and process

SharedStream ¶

Bases: Generic[T]

A ring of items in shared memory, sent by one process and received by up to max_readers readers.

Create it with create in one process and open it with attach in others. Every item has the type given there: any type a SharedBox field takes, except a reference to a box.

sender ¶

sender() -> StreamSender[T]

Return the stream's sender for this process.

Raises:

Type Description
StreamBusyError

If another live end holds the sender.
EndOfStream

If the stream has ended: its sender closed, or a reader found the sender's process dead. There is no second sender after that.
Notes

A sender whose process died is replaced, unless a reader already found it dead, which ended the stream.

The stream keeps its sender until it is closed, so dropping the returned object does not end the stream, and another sender() call in this process raises StreamBusyError until then.

close() -> None

Close every sender and reader made from this object, then let go of the stream.

Closing the sender ends the stream for its readers.

Other processes keep the stream. Using a closed stream raises StreamClosedError.

StreamSender ¶

StreamSender(stream: SharedStream[Any], native: Sender | Reader)

Bases: End, Generic[T]

The sender of a stream: one per stream, in the process that holds it.

SharedStream.sender returns it. The stream keeps it open until close(), or until the stream is closed or the process dies; dropping the object does not close it. Closing it ends the stream: readers receive what is buffered, then EndOfStream.

StreamReader ¶

StreamReader(stream: SharedStream[Any], native: Reader)

Bases: End, Iterator[T], AsyncIterator[T], Generic[T]

A reader of a stream, in the process that opened it.

SharedStream.reader returns it. for item in reader and async for item in reader receive until the stream ends.

Notes

Receives made with receive and the like must not overlap receives made with receive_future or async for on the same reader: an item that an awaiting task gave up is kept and returned by the next receive, which may then come after a later item.

position property ¶

position: int | None

The position of the last item received, None before the first.

ReaderStatistics.position is the position of the item received next, so right after a receive it is one more than this.

missed property ¶

missed: int

Items a lossy or latest reader skipped; always 0 for a lossless reader.

events property ¶

events: ReaderEvents

The reader's psygnal signals: received as (item, position) for each item, and ended once per delivery.

Connecting the first received callback starts delivery on the reader's background thread, and disconnecting the last one stops it. While delivery runs, every other way of receiving from this reader raises RuntimeError, also after the stream has ended, until the callbacks disconnect: one reader cannot hand an item to two consumers, so open a second reader for that. Callbacks run on the background thread; connect with thread="main" and call psygnal.emit_queued() to run them on the main thread. A callback that raises is logged to the sharedbox logger and delivery goes on, unless the receive itself fails: that is logged too, and callbacks then receive nothing more until a received callback connects or disconnects. Delivery runs only while received has a callback, and ended fires only then. A slow callback makes a lossy or latest reader miss items and holds the sender back for a lossless one. Right after delivery stops, the _nowait forms may raise WouldBlock until the delivering call has returned.

Notes

Starting and stopping delivery relies on psygnal calling the private methods SignalInstance._append_slot and _remove_slot.

receive ¶

receive(timeout: float | None = None) -> T

Return the next item, with new arrays.

Raises:

Type Description
EndOfStream

If the sender closed or died and every item it sent was received.
TimeoutError

If timeout seconds pass first.
StreamClosedError

If this reader is closed, before or during the wait.
Notes

A blocking receive first waits for calls already on the reader's background thread, such as an outstanding receive_future, and returns the item after theirs; that wait counts against timeout. An interrupt such as Ctrl-C during the call may lose the item being received.

receive_into ¶

receive_into(out: Any, /, *, timeout: float | None = None) -> T

Return the next item, with its arrays read into the arrays in out.

out has the item's shape: an array for an item that is an array, a tuple with an entry per member for a tuple item, and a mapping from member name to entry for a record item. An entry is an array, None for a member decoded as usual, or, for a member that is a record or a tuple, an out of its own shape. A name left out of a mapping is decoded as usual. The item returned holds your arrays, filled in place. Allocate the arrays once and pass them to every call:

image = np.empty((480, 640), np.uint16)
frame = reader.receive_into({"image": image})

An item that a cancelled receive_future or anext had already received is returned by the next receive of any kind, and holds the arrays of the call that received it, not out.

A member that is a list, set, frozenset, dict or tuple[T, ...] takes None, since an array cannot be a collection element, and an item that is a collection has no array to read into. Every check runs before anything is received, so a refused call takes no item.

Raises:

Type Description
TypeError

If out does not have the item's shape, names a member the item does not have, gives an array for a member that is not an array, or holds an array that cannot be written; or if the item holds no array at all.
ValueError

If an array has another dtype or shape than its member.
Notes

A blocking receive first waits for calls already on the reader's background thread, such as an outstanding receive_future, and returns the item after theirs; that wait counts against timeout. After an exception the contents of out are unspecified. out must not be written to or resized from another thread during the call. An interrupt such as Ctrl-C during the call may lose the item being received.

receive_nowait ¶

receive_nowait() -> T

Return the next item, or raise WouldBlock if none is waiting.

It also raises WouldBlock while a call on the reader's background thread is still running, such as a cancelled anext or a delivery stopping after the last events.received callback disconnected, so an item that call hands back is received first.

receive_into_nowait ¶

receive_into_nowait(out: Any) -> T

As receive_into, raising WouldBlock if no item is waiting.

iter_into ¶

iter_into(out: Any) -> IterInto[T]

Return an iterator of items read into the arrays in out, as receive_into takes it, for for.

close ¶

close() -> None

Close this reader and drop items kept from cancelled receives.

receive_future ¶

receive_future(out: Any = None) -> Future[T]

Return a future of the next item, received by this reader's background thread.

The future is a concurrent.futures.Future, so concurrent.futures.wait and asyncio.wrap_future take it. Its exception is EndOfStream once the stream has ended, and StreamClosedError if the reader closes first. out, when given, is what receive_into takes.

Cancel the future before it starts to drop it. A running call cannot be cancelled: cancel() returns False, as for any Future, and the call goes on. An item it takes after its future was abandoned, or after an asyncio.wrap_future around it was cancelled, is lost. To wait on several readers, keep one outstanding future per reader and submit a new one only for the readers whose future completed.
